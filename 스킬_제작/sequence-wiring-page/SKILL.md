# 결선하기·단자대 번호매기기 페이지 만들기 (요청 0028 방식)

> 엔진 위치(코드 사본을 스킬에 두지 않는다): `핀번호_작업/v2_엔진분리/공용/`(wire-engine·tb-engine·wire-validate·panel-render·panel-library·wire-page.css), 이력 `공용/ENGINE_CHANGELOG.md`, 전체 구조 레포 맨 위 `ARCHITECTURE.md`.
> 견본: `회로/wire-001.js`(전기), `회로/wire-e01.js`(승강기).

## 절대 규칙

- **공단 도면의 이미지·PDF·원문 문구를 저장소·사이트에 넣지 않는다.** 배치도·배관도는 원본을 보고 치수·순서만 읽어 mm 좌표로 적는다. 그림은 `공용/panel-render.js` 가 새로 그린다. 원본 이미지를 scratch 에 남기지 않는다.
- **엔진·기존 데이터를 고치지 않는다.** 회로 하나를 추가할 때 바꾸는 것은 `회로/wire-NNN.js` 와 페이지 `index.html` 뿐이다. `device-library.js`, `pin-engine.js`, `pin-validate.js`, `diagram-render.js`, `circuit-*.js` 는 읽기만 한다. 공용 결선 파일(`panel-library.js` 등)을 고쳐야 하면(예: 리밋스위치 단자 종류 추가) 이유를 보고서에 적고 001·e01 검사를 다시 돌린다.
- **새 ID 를 만들지 않는다.** 점은 핀번호 적기와 같은 `'<회로>/<태그>:<핀>'`. 핀 값은 `circuit-NNN.js` 의 `answerKey` 그대로(EOCR 공통 10, 릴레이 1·8조, PB N/C/O). 칸이 없는 점만 이름을 더한다: 퓨즈 `F:1~4`, 제어함 단자대 `TB5:n`·`TB6:n`, 외부 단자대 `TB1~TB4`, 승강기 `TB1`(전원)·`TB2`(출력)·Y-Δ 는 `TB3`(X Y Z). 셀렉터 N 두 개만 `SS:SS#ssM`, `SS:SS#ssA`.
- 비밀번호·키를 평문으로 쓰지 않는다. 삭제하지 않고 `99_삭제_대기/` 로 옮긴다. `git add <경로>` 로 내가 바꾼 파일만 커밋한다. push·배포는 따로 한다.

## 작성자가 정한 규칙 (2026-09-26, 바꾸지 말 것)

- **단자대 칸 번호에는 정답이 없다**(2026-09-27 작성자: "배선이 꼬일 뿐 실격·채점 제외는 아니다"). 화면·문서에서 칸 번호를 '정답'이라고 부르지 않는다. **'권장 배치(예시)'** 라고 쓰고, 배관도 순서를 따르면 선이 엇갈리지 않는다는 이유와 다르게 배치해도 틀린 게 아니라는 점을 같이 적는다. 퀴즈는 칸 번호를 묻지 않는다.

- **단자대 칸 배치 규칙(작성자 확정, 요청 0043)** — `layout: 'block'`:
  1. TB5(위)·TB6(아래)는 각각 **10P+10P**(1~10 ‖ 11~20). 위쪽으로 나가는 관 → TB5, 아래쪽 관 → TB6. 그룹 순서 = 관 순서(관이 제어함을 나가는 자리 왼쪽 → 오른쪽, J 박스에서 나누면 도착 상자가 왼쪽인 것부터). 데이터(`groups` 순서)를 그대로 쓴다.
  2. 단위는 **관 덩어리**: 한 관으로 나가는 그룹(J 박스에서 나눠 쓰면 그 그룹들 전부, 첫 관 `pipes[0]`이 같은 이웃 그룹)은 빈칸 없이 붙인다.
  3. 관 순서대로 덩어리를 10P 블록에 채운다. **덩어리는 10‖11 경계를 넘지 않는다**(안 들어가면 통째로 다음 블록).
  4. 블록 안에서는 **양끝으로 벌린다**(관이 나가는 자리처럼): 덩어리가 둘 이상이면 첫 덩어리는 블록 왼쪽 끝, 마지막은 오른쪽 끝, 가운데는 사이 빈칸을 고르게. 덩어리가 하나면 앞 블록은 왼쪽 끝(1번), 뒤 블록은 오른쪽 끝(20번).
     예: 위쪽 관 ab(J)·c·d → ab 1~, c 11~, d ~20 / a·b·cd(J) → a 1~, b ~10, cd ~20 / 아래쪽 관 4개 따로 → 1~4 · 7~10 ‖ 11~ · ~20.
  5. **칸이 모자라면 되는 데까지만 적용**: 3이 안 되면(009 TB5, 19칸) 피할 수 없는 덩어리 하나만 경계를 넘기고 나머지는 2~4대로. 한 그룹이 10칸을 넘거나 단자대에 다 안 들어가면 검사기 오류.
  6. **그룹 안 기구 순서는 자유**(PB0·PB1 / PB1·PB0, RL·GL / GL·RL 모두 정답). 한 기구 단자는 붙여서 순서대로(RL1, RL2) — 떨어져 있으면 검사기 오류. 모범답안(권장 배치)은 `basic` 순서 그대로.
  - 예: 001 TB5 = PB·SS(J) 1–7, TB1 11–14, RL·GL 17–20 / TB6 = YL·BZ 1–4, TB3 7–10, TB4 11–13, TB2 17–20.
  - 칸 번호는 엔진(`wire-validate.js` `blockLayout`)이 계산한다. 예전 방식 `'pipe'`(관 위치 = 칸 위치)·`'pack'`(gap 칸씩 띄움)도 코드에 남아 있지만 전기 001~018 은 `'block'` 을 쓴다.
  - 규칙과 데이터가 안 맞아도 데이터를 고쳐 맞추지 말고 보고한다.
- 구간(nets)에는 칸 번호를 적지 않고 **별칭 `'NNN/TB@바깥점'`**(예: `'001/TB@PB0:N'`)을 쓴다. 자리 방식을 바꿔도 구간은 그대로다.
- 칸 이름 = 바깥 기구 단자 이름(램프 1·2, PB N·C/N·O, TB1 L1·L2·L3·PE, TB2/TB3 U V W PE, TB4 E1 E2 E3). 가로 단자대는 왼쪽부터, 세로는 위부터.
- 공통단자는 기본으로 쓰지 않는다(`basic`). 심화는 `common`(같은 점을 한 칸으로, 공통은 그룹 맨 앞). **셀렉터만 기본부터 SS·A·M 세 칸**(N 두 개를 스위치에서 묶음, SS·M·A 순서도 됨).
- FLS E3 접지: TB6 의 E3 칸. 보호도체 건너 묶기는 **E3 칸에서 마지막으로 끝난다**(E3 칸 안쪽 = FLS 1번 선 + 접지선 2가닥).
- 한 단자(나사)에 3가닥 이상 금지. 제어판 밖으로 나가는 선은 모두 TB5·TB6 을 거친다(전기).
- 전기 선: 주회로 2.5㎟ L1 갈색·L2 흑색·L3 회색, 퓨즈 1차도 주회로색, 퓨즈 2차부터 보조 1.5㎟ 황색, 보호도체 2.5㎟ 녹색-황색, FLS E1~E3 는 보조선.
- 승강기: MCCB 없음(생략·직결, `omit.MCCB`), 기구 직결(중계 단자대 없음), 주회로 2.5㎟ 적색, 보조 1.5㎟ 청색, 기구와 기구 사이 배선 금지. 제어 전원은 EOCR 1·3번(전원측)에서 보조선으로 딴다.
- 퓨즈 단자 이름(1차 왼쪽·오른쪽, 2차 왼쪽·오른쪽)은 결선 화면 표시용이다. 핀번호 적기에는 없다.

- 전기 001~018 은 모두 **위 관 3 · 아래 관 4**(제어함 둘레에서 나가는 관 수, 2026-09-28 데이터로 확인). 수가 다르면 판독부터 다시 본다.

- 관·선이 다른 상자(TB1 등)를 뚫거나 상자 이름 글자를 가리지 않게(0046 009, 0050 010 T3).

## 요청 0030 으로 생긴 기능 (데이터 필드는 늘지 않았다)

회로 데이터를 더 적을 것은 없다. 아래는 모두 기존 `nets`·`terminalBlocks`·`piping` 에서 엔진이 계산한다. 그래서 **기존 필드의 뜻을 지키는 것**이 중요하다.

- **구역 나눠 보기**(결선하기, 시뮬레이션의 view-tabs 모양): 전체 / 주회로(`group:'main'`) / 제어회로(`group:'aux'`) / 보호도체(`group:'pe'`, 있을 때만). 한 구간 안에 다른 종류 선이 있으면(체인의 `wire` 의 `kind`) 그 구역에도 함께 보인다 — 예: 승강기 H·N 구간은 `main` 이지만 제어 전원 보조선 체인이 있어 제어회로에도 나온다. `pe` 구간은 보호도체 구역에만. → **`group` 은 세 값 중 하나로, 선 종류는 실제 선에 맞게** 적는다.
- **자유 탐색**(결선하기, 시뮬레이션의 "자유 조작" 토글 자리): 회로도의 핀번호 칸·칠한 선·`circuitPoints`, 배치도 단자(`data-key`), 배관도 단자·단자대 띠 칸(`data-cell`)을 누르면 점 → 구간 역인덱스(`WIRE_MODEL.pointNets`)로 그 구간을 보여 준다. 구역을 좁혀 두면 다른 구역 점은 "○○ 구간이에요 · 전체로 보기" 안내. → 모든 구간이 회로도에서 눌릴 수 있어야 한다(검사기 `누를 수 있는 구간 X / Y`, 모자라면 경고). 회로도에 칸이 없는 점은 `circuitPoints` 로.
- **단자대 퀴즈**(전기, 탭 ②·③): ② 관 순서대로 줄 세우기 — 정답은 `WIRE_MODEL.pipeOrder(W).expected`(관이 제어함을 나가는 자리). 버튼에는 그룹 `name` 과 상자 `label` 만 보이고 `mark`(ⓐ…)는 숨긴다. ③ 한 칸에 묶어도 될까 — 같은 그룹(`basic`) 안 두 바깥 점, 정답 = 같은 구간인지(`WIRE_MODEL.tbQuizPairs`). → 그룹 `name` 에 순서를 드러내는 말(①, 첫째 …)을 넣지 않는다. 한 그룹의 `basic` 은 한 상자(`box`)의 점만.

## 하지 않는 것

- 결선하기 채점(배치도에서 직접 잇기)은 0062 에서 만드는 중이다(위 '자리만' 절). 단자대 퀴즈는 칸 번호를 채점하지 않는다.
- 공용 엔진(`wire-engine.js`, `tb-engine.js`, `wire-validate.js`, `panel-render.js`, `wire-page.css`)은 회로를 넓히는 작업에서 고치지 않는다. 필요하면 보고서에 적어 요청한다.
- 범위 밖 회로를 한꺼번에 만들지 않는다. 요청이 정한 번호만.
