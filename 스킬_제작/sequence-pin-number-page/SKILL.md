# 핀번호 적기 페이지 만들기

학생이 시퀀스 회로도의 각 단자 옆 칸에 소켓 핀 번호를 적고, 칸을 누르면 그 기구의 내부 결선도를 보며 적는 연습 페이지를 만든다. 001번이 기준 구현이다. 화면 그림은 기구 규격(핀 배치·접점 연결)을 바탕으로 **우리가 새로 그린 SVG** 다. 원본 도면 그림을 따라 그리거나 겹쳐 그리지 않는다.

> 엔진 위치(코드 사본을 스킬에 두지 않는다): `핀번호_작업/v2_엔진분리/공용/` — 이력은 같은 폴더 `ENGINE_CHANGELOG.md`. 전체 구조는 레포 맨 위 `ARCHITECTURE.md`.

## 0. 절대 규칙

- **저작권**: 한국산업인력공단 공개도면의 이미지·PDF·원문 문구는 저장소·사이트·scratch 어디에도 넣지 않는다(근거: 도면 PDF 11-4쪽 저작권 문구, 요청 0001). 원본 PDF는 핀 번호와 접점 종류를 **읽는 데만** 쓴다. 판독용 PNG는 시스템 임시 폴더에만 만들고 지운다. 원본은 큐넷 공개문제 자료실 링크로 안내한다. 산출물 폴더에 png·jpg·pdf(공단 도면)가 0건인지 확인한다.
- **엔진은 열지 않는다**: 새 회로는 `회로/circuit-NNN.js` 와 페이지 `index.html` 두 파일만. 공용 파일(`pin-engine.js`, `pin-validate.js`, `diagram-render.js`, `device-library.js`, `pin-page.css`, `steps.js`)을 고쳐야 하면 따로 요청하고, 고치면 `ENGINE_CHANGELOG.md` 에 한 줄을 더한다.
- **검사기를 통과하려고 학생 답 칸(`layout.items`)을 바꾸지 않는다**(요청 0031→0039·0040, e07 사례). 칸의 위치·순서·`title`·`slots` 순서는 학생이 적는 답과 정답표의 순서다. 검사기가 막으면 그림(`layout.drawing`)을 고치거나 보고한다. e07 FR 상단 접점은 **공통 8번이 아래**가 이 도면의 정답이다 — 칸 순서 `[8, 6]`, 제목 "FR 상단 a접점 · 공통은 아래". 규칙("공통은 위")과 도면이 다르면 도면을 따르고 보고한다.
- **핀 번호는 추정하지 않는다**: 원본 PDF를 확대해 눈으로 읽는다(번호는 PDF 글자가 아니라 그림 안에 있다). 새 경우가 나오면 추측하지 말고 질문 md 를 만들어 선생님이 답을 달게 한다.
- 문서·메시지는 모두 한국어. 비밀번호·키·토큰은 평문으로 쓰지 않는다. 삭제하지 않고 `99_삭제_대기/` 로 옮긴다. 커밋은 `git add <내가 바꾼 경로>` 만. 서버·배포는 따로 한다.

## 3. 선생님 확정 규칙 (2026-09-20, 바꾸지 말 것)

| 경우 | 판정 |
|---|---|
| 결선하면 동작하고 위아래 순서도 맞음 | 정답 |
| 릴레이 접점을 어느 것부터 1조로 쓰든 | 정답 |
| 공통단자 공유(3–1과 1–4가 같은 점) | 정답. 설명은 '심화'에서만(지금 버튼 숨김, 아래 5장) |
| 접점 위아래(가로는 좌우) 뒤집힘 · 코일 위아래 뒤집힘 | 경고 |
| EOCR 공통에 11 | 경고 (10으로 통일) |
| 푸시버튼을 숫자로 | 경고 + 실물 단자 확인 안내 |
| a/b 바뀜, 없는 번호, 같은 핀을 서로 다른 점에 씀 | 오답 |
| 빈 칸 | 오답 (MCCB만 비워도 됨, 점수 제외) |

- 공통단자는 위(가로 접점은 왼쪽) — 도면이 다르면 도면(e07). 코일 2 위·7 아래, 6 위·12 아래. FLS 전원 5 위·6 아래.
- 릴레이: 처음 적는 X 접점에 1, 다음에 8. 1이면 a 3·b 4, 8이면 a 6·b 5. EOCR: b 10–4, a 10–5.
- 푸시버튼: a접점 위 N·아래 O, b접점 위 N·아래 C. 셀렉터: 위 칸 SS, 아래 칸 A 또는 M(실물 N 두 개 묶어 SS, C(위)=M, O(아래)=A). 램프·부저: 위 1, 아래 2. MCCB: 1 2 3 / 7 8 9(선택). 주회로 EOCR·MC 위 1 2 3, 아래 7 8 9.
- 점수 방식은 화면에서 고름: ① 정답 1·경고 0.5·오답 0 ② 경고는 표시만.
- 제출: 결과 PNG(이름·학번·점수·회로도·틀린 이유). 서버에 학생 답을 저장하지 않는다. 파일 이름은 **영문·숫자만**(`pin-0NN-학번-날짜.png`) — 한글 이름은 브라우저에 따라 확장자 없는 `download` 로 떨어진다.

## 4. 접점 기호 (설계 결정 7 — 회로 앱 접점개선판과 같게)

- 한시 접점 = **삼각형**, 플리커 접점 = **검은 마름모**(양쪽 삼각형), 순시 접점 = 표시 없는 **일자 막대**. 푸시버튼 = 짧은 가로선(가로 PB0 누름대는 위쪽 단일 막대), 셀렉터 = 선택 표시 + 기계적 점선, EOCR = ×.
- 기호는 `diagram-render.js` 가 `feat`(`td` 한시 · `fl` 플리커 · `ovl` EOCR · `pb` · `ss` · `ls`) 값으로 그린다. 데이터에 `feat` 를 맞게 적는 것만 하면 된다. 순시 a 에 `td` 를 달지 않는다.

## 5. 학습 흐름 안에서 핀번호의 자리 (D0010)

- **시뮬레이션이 메인, 핀번호·회로해석은 실습.** 단계 줄 순서: 시뮬레이션 → 회로해석 → 핀번호 적기 → 단자대 번호매기기(전기만) → 결선하기. 단계 줄과 회로 이동(◀ 이전 · 고르기 · 다음 ▶, 요청 0056)은 `steps.js` 가 그린다 — 페이지에는 `<nav id="steps"></nav>` 만 둔다.
- 과정: 전기기능사 `c` = 3자리(`001`~`018`, 서버 `/c/NNN/pin/`), 승강기기능사 `e` = **2자리**(`01`~`10`, 데이터 id `e01`, 서버 `/e/NN/pin/`) — 설계 결정 14. 번호에 한글을 섞지 않는다(주소·파일 이름·ID는 영문·숫자).
- 숨긴 기능(코드는 보존, 되살릴 때 한 줄만 지움): **'심화: 공통단자 함께 쓰기' 버튼**(요청 0044, `pin-engine.js` 1줄, `deepText` 보존), **'실물 사진 자리' 빈 상자**(요청 0060, `pin-page.css` 의 `.photo { display: none; }`). 실물 사진은 선생님 직접 촬영분이 생길 때만(인터넷 제품 사진은 게시 불가).

## 6. 새 회로 만드는 순서

1. 초안: `node 검사/앱에서_초안뽑기.cjs 0NN "<앱 폴더>/circuit-diagram.js" > 회로/circuit-0NN.초안.js` — 접점 id·기구·a/b·순시/한시·net·정답 제안이 채워진다(좌표·주회로·전극·번호 없는 기구는 빈칸). 승강기는 회로 앱이 없던 때 도면에서 직접 적었다(요청 0013).
2. 원본 6·7쪽(승강기 5쪽)을 확대해 읽고 초안을 고친다. 앱의 `kind` 가 틀린 경우가 있다 → 원본을 따르고 보고.
3. `layout.drawing` 에 회로도를 그린다. 도형: `rect·text·term·dot·line·wire·breaker·mc·fuse·motor·earth·item·items`. 접점·코일 기호는 `{t:'items'}` 한 줄. `layout.viewBox` 를 회로 크기로(PNG 크기도 이것을 쓴다).
4. `layout.items` 의 x·rows(칸 위치)와 net, `answerKey` 를 채운다. 같은 선으로 이어진 단자 = 같은 net 이름. 기본 칸 자리가 선·원을 가리면 그 항목에만 `slots: [{x, y, net}, …]` 를 적어 옮긴다 — **순서·net 은 그대로**(예: 승강기 EOCR 코일 칸은 원 옆 x 370, 요청 0050b B안).
5. 새 기구 종류는 `device-library.js` 에 한 번만 추가(원본 위치 `source`, 필요하면 `needsReview`) → 엔진 변경이므로 ENGINE_CHANGELOG.
6. `pin-verification-table.md` 에 원본 위치와 함께 추가. 자동 제안 정답은 그대로 믿지 않고 검증표와 대조한다.
7. 페이지: `001/index.html`(전기) 또는 `e01/pin/index.html`(승강기)을 복사해 `data-circuit` 과 `circuit-NNN.js` 경로만 바꾼다. 인라인 `<script>`·`eval`·바깥 주소·브라우저 저장소 금지(서버 CSP `script-src 'self'`).

## 7. 검사 (반드시, 결과를 보고서에 붙인다)

| 도구 | 잡는 것 |
|---|---|
| `node 검사/검사하기.cjs NNN` | 데이터: 없는 태그, 라이브러리에 없는 핀, 정답표 빠짐, 같은 핀 두 점, 코일 없음·접점 초과, 순서 빠짐, 칸 겹침. **오류 0** |
| `node 검사/앱대조.cjs NNN "<앱>/circuit-diagram.js"` | 회로 앱과 접점·코일·net 묶음 대조(Playwright). 차이는 원본으로 판정 |
| `node 검사/겹침검사.cjs NNN` (또는 `all`) | **그린 모양**: 선이 코일·램프 원 관통(오류), 입력 칸이 단자 가림(오류), 입력 칸 관통(경고), 점 없는 교차(정보). node 만으로 돈다. `--rev 커밋` 으로 전후 비교 |
| `node 검사/오류예시.cjs` | 검사기 자체가 5가지 틀린 예를 잡는지 |

- **검사기 통과 ≠ 그림 정상**(0039: 004 E2·E3가 FR 코일 원을 지나가는데 검사하기 0건). 그림을 바꿨으면 겹침검사 + 화면 캡처를 눈으로 본다.
- 브라우저(Chromium/Playwright): 정답표를 다 넣으면 전부 정답 · 사례(릴레이 순서 바꿈, 공통 공유, 같은 핀 두 곳, 위아래 뒤집힘, a/b 바뀜, EOCR 11, 코일 뒤집힘, PB 숫자, MCCB 비움, 순시/한시 바뀜) · 모든 칸 선택 상태 SVG 를 DOMParser 로 파싱(속성 중복이면 PNG 저장이 조용히 실패) · PNG 저장 실제로 누름 · CSP 헤더 붙인 서버에서 위반 0 · 1366×768 과 390px 가로 넘침 없음.

## 8. 배포 준비 

- `steps.js` `ready.pin` 에 번호를 더하는 것은 **배포 승인 뒤**. 그 전에는 `draft` 로만.
- 공용 CSS·JS 를 바꿨으면 `deploy/build_staging_all.py` 의 `VER`(`?v=` 값, 예 `20260928g`)를 올린다. 배포는 허용목록(스테이징 → `MANIFEST.sha256`) 방식이고, 서버에서 직접 고치지 않는다.
- 보고서에 결과 파일 위치, 검사 출력, 확신하지 못한 것·물을 것을 우선순위로 적는다. "완료"에는 증거(검사 출력·해시·캡처)를 붙인다. 선생님 승인 전에는 다음 회로로 넘어가지 않는다.
